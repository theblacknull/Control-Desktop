# Local sandbox platform findings

The evidence ledger for the local sandbox providers. Each row names one measurement, what it observed, and the conclusion the provider design rests on. Rows are cited by id from the provider code and docs.

Host for every row: macOS 27.0.1 arm64, Xcode `swiftc` 6.4.2, measured 2026-11-02 unless a row says otherwise.

| id | probe | observed | conclusion |
| --- | --- | --- | --- |
| S1-1 | A binary that uses Virtualization.framework, run without the `com.apple.security.virtualization` entitlement | `VZVirtualMachine` init refuses it with "The process doesn't have the com.apple.security.virtualization entitlement". The same binary, ad-hoc signed with that entitlement, validates. | The VM host must carry the virtualization entitlement, and `codesign -f -s -` with an entitlements file is enough. |
| S1-2 | The ad-hoc signed binary with a `com.apple.quarantine` xattr added, then run | Gatekeeper kills it (exit 137). A locally built file carries no quarantine flag. | Build and sign the VM host on the user's Mac; never ship a prebuilt one. |
| S1-3 | Apple's IPSW catalog and `VZMacOSRestoreImage.fetchLatestSupported` on this host | The catalog lists one image, `UniversalMac_27.2_26B123_Restore.ipsw`, with `FirmwareSHA1 617360e5619dbb424ed3774b98732bb3cfeacc0b`. `fetchLatestSupported` failed with "The restore image catalog failed to load". | The provider reads Apple's catalog directly and verifies the SHA-1, and never relies on `fetchLatestSupported`. Only the latest image is offered. |
| S1-4 | An APFS clone of a set-up macOS 26.4 guest bundle, booted headless from a command-line host with no NSApplication | Over SSH, `agent-desktop permissions` reported accessibility and screen_recording granted. `snapshot --app TextEdit -i` returned ok, ref_count 25, complete true. | A headless command-line VM host is enough to run agent-desktop in the guest, and grants made in the guest persist in clones of its disk. |
| S1-5 | A clone with a fresh `VZMacMachineIdentifier` and a fresh MAC address | The clone got a new DHCP lease, 192.168.64.3, found by MAC in `/var/db/dhcpd_leases`. It was reachable over SSH within 15 s, and both grants and the snapshot result were unchanged. | `clone` gives each sandbox its own machine identifier and MAC, and `ip` finds the address by MAC. |
| S1-6 | `requestStop()` on a macOS guest, with and without open documents | The guest never shut down within 60 s in either case. The hard `stop()` ended the VM both times. Guest `sudo` asked for a password, so shutdown over SSH was not available. | `vmhost` waits briefly after `requestStop()`, then hard-stops. The hard stop is the normal path. |
| S1-7 | `debian:bookworm-slim` container with xvfb, openbox, dbus, at-spi2-core, libatk-bridge2.0-0 and mousepad, plus the released agent-desktop 1.0.2 aarch64 Linux binary | `snapshot --app mousepad -i` returned ok, ref_count 271, complete true. Image size 745 MB. | The Docker provider's image needs no extra accessibility setup beyond these packages, and the released Linux binary drives it. |
| S1-8 | Installing macOS 27.2 from its image on this 27.0.1 host | Not measured. No image was available locally. | Open. The install-from-image path must be run end to end before it is claimed to work. The docs mark it experimental, and CI compiles and signs `vmhost.swift` but does not install an image. |
